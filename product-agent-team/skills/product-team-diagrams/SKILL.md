# 结构化做图

把信息转成能解释关系和决策的图。先明确本图回答的问题、读者阅读顺序和每类连线的含义，再安排版式。简单关系可直接用 Mermaid 或表格；用户需要插入材料或导出图片时，选择 SVG，并按需导出 PNG。

澄清节奏、任务范围与交付状态沿用 [共享工作流](../../workflow.md)；事实、推导、示例与回写资格沿用 [轻量产品模型与回写](../../project-memory-rules.md#轻量产品模型与回写)。专业建议可以画成明确标记的建议图，不将补出的能力、业务名称、数值、日期或关系当成产品事实。

## 资料分工

按本轮图型和输出方式读取，不要求每次加载全部资料：

| 资料 | 何时读取 | 唯一维护的内容 |
|---|---|---|
| [参考图库](references/example-gallery.md) | 选择合适的 SVG 版式或示例 | 图型索引、示例提示词及 assets 路径 |
| [模板布局](references/template-first-workflow.md) | 使用步骤流、图标卡、矩阵、时间线等 SVG 模板 | 模板容量、坐标变量、专用连接带及几何检查 |
| [视觉样式](references/visual-style-constraints.md) | 制作 SVG/PNG 汇报图，或修正字体、留白、色彩和可读性 | 字体、色彩、卡片风格、语义换行及渲染检查 |

示例是可改造的中性结构，不是业务规则。模板合适时复用；没有匹配结构时可自定义，不能为套模板删掉必要分支或改变事实。

## 关系建模

对复杂图先在内部列节点和连线：节点记录名称、类型和必要说明；连线记录起点、终点、关系和条件。小图不额外生成模型文件。

- 执行顺序、条件分流、状态变化使用明确且可区分的表达；一张图以一个核心问题为主，多类关系并存时分区并说明连接关系。
- 区分必经与按需步骤，按需动作标出触发条件。准备信息、判断路由和执行动作各有职责，不把路由落点画成最终完成。
- 面向产品读者优先表达用户动作、系统判断和结果。技术字段、接口名、内部状态只在有助理解时出现；陌生术语在首次出现时用业务语言解释。
- 删除同义重复节点和重复说明，将长解释移到图外。

按关系选图型：

| 主要关系 | 图型与语义检查 |
|---|---|
| 从触发到结果的操作顺序 | 流程图 / 步骤流；每条范围内路径有落点，异常出口按已知规则表达 |
| 有条件的不同处理 | 决策树；判断写成问题，分支有明确条件和目标 |
| 对象状态变化 | 状态机；状态写状态名，转换线上写事件，按任务覆盖终态、异常和恢复 |
| 多角色或工具消息交互 | 时序图 / 泳道；参与者清楚，箭头有动作含义 |
| 模块、数据与权限依赖 | 分层架构图；标注模块边界、依赖方向及适用的数据/权限边界 |
| 阶段、计划和迁移 | 时间线 / 迁移路径；区分确定日期、阶段顺序与建议安排 |
| 职责、规则或方案比较 | 矩阵表；先明确行列含义，避免用流程箭头表达并列关系 |
| 一个入口关联多个能力 | 三栏 / 中心辐射；节点过密时分组或改矩阵 |
| 指标、趋势与转化 | 数据图 / 漏斗；数值有来源，说明性模拟数据显式标记，不能作为分析证据 |

涉及 Agent 或异步系统时另查：

- 基础上下文、按需检索、工具结果与任务状态是否被误并成一个黑盒。
- 普通对话是否被错误画成必经检索；路由之后是否仍有执行和交付。
- 任务流程与断点恢复状态是否混淆；持续保存、状态查询、重连、继续、完成和失败分支仅按实际规则绘制，不能假设断网必然触发保存或重试安全。

## 生成与检查

逻辑明确后选择布局，专业几何和视觉要求分别使用上表对应 reference，不在本文件另立数值阈值。内容超载时精简说明、分组、换模板或拆图，不通过删掉必要条件或压缩字号掩盖问题。

交付前完成与当前输出相符的检查：

1. **结构**：从起点沿每条路径读到结果，检查跳步、死路、缺少条件、方向错误、权限边界和路由/结果混用。
2. **读者理解**：读者能说清从哪里开始、下一步是什么、何时分支、最终得到什么；图例和专业词够用。
3. **布局与渲染**：SVG/PNG 按相应 reference 检查容量、对齐、文本和连线。用可用工具预览完整图及实际使用尺寸；Mermaid 同样核对语义，能渲染时检查渲染结果。
4. **交付状态**：仅报告实际完成的检查。无渲染能力时交付可用源文件并说明视觉未验证，不把语法有效称为排版通过。

用户反馈“图不对”时，先定位事实、关系、图型或信息密度，再修正视觉；反馈排版问题时定位坐标、连线、字号或边距。修复后复查受影响结构与渲染结果。
