# HTML 设计稿与产品 Demo

交付用户可以直接打开的 HTML 页面。任务范围与澄清节奏沿用 [共享工作流](../../workflow.md)，事实、演示样例与回写资格沿用 [轻量产品模型与回写](../../project-memory-rules.md#轻量产品模型与回写)。静态与可点击模式根据用户要求选择，只有模式缺失且会改变交付时才询问。

## 范围与模式

- **静态设计稿**：用户要求静态页面、设计稿或“看看页面”时，完整呈现指定页面的布局、内容和必要可见状态。页面内锚点或展示切换可按需要提供，不强制模拟提交、编辑或完整业务流程，不声称交互已实现。
- **可点击 Demo**：用户要求可点击演示、交互原型或体验指定路径时，让范围内主要动作有反馈，覆盖任务完成、适用的异常与恢复；模拟数据和状态不冒充真实服务。
- **局部修改**：复用已有文件和已确认设计，只更新受影响页面、组件与状态，并验证相邻影响。不自动重建全产品导航、所有页面或后端。
- 首次使用、空状态、权限等按本轮路径适用性检查；若核心任务依赖对象初始化，须交代创建入口或已确认的存在前提，不凭空增加业务范围。关键规则未定时按共享工作流处理。

## 输出要求

- 新建稿默认是自包含完整 HTML，包含文档结构、CSS 和需要的 JavaScript；修改现有稿时保持其合理组织方式，用户指定其他结构时遵从要求。
- 页面包含与范围相符的信息层级、内容区及必要操作，不为单页强加完整产品导航。采用可信业务文案；示例姓名、图片和数据仅作演示，不能冒充用户真实资料。
- 优先使用已确认设计规范、参考图和现有样式，使用语义化 HTML、CSS 变量、flex/grid 及目标端适用布局。视觉偏好未明确时可作合理设计选择并简述，不因此新增审批。
- 默认无需真实后端或外部连接。可点击模式中，范围内控件具有可见反馈；范围外动作可省略或明确不可用。静态模式中的展示控件不宣称可操作，必要时在交付说明中注明。
- 需要延续现有产品、多页面设计或较复杂交互时读取 [前端标准与 QA](references/frontend-standards-and-qa.md)，按适用项检查设计语言、样式复用和状态。
- 不输出无意义占位、内部字段名、错误调试文案或无关装饰；只覆盖实际适用的空、加载、成功、错误、权限和恢复状态，不为凑状态清单虚构流程。
- 默认交付文件链接及简短说明，说明静态/可点击模式、已检查内容和实质限制；用户明确要求只给 HTML 源码时才只输出完整源码。无需生成 Figma 文件。
- 页面中的链接必须是真实可用的链接或页面内锚点，不编造外部服务地址。

## 交付前检查

1. 文件可独立打开，样式和脚本均已包含。
2. 在本轮目标视口检查溢出、遮挡、文字换行；用户要求多端时覆盖相应尺寸，不强制给小程序设计新增桌面产品流程。
3. 文案面向普通业务用户，避免技术术语和内部字段名。
4. 静态模式检查已约定页面及可见状态；可点击模式实际操作指定核心路径和适用异常。改动复查影响范围，不为局部需求强制覆盖产品全貌。
5. 有渲染/操作工具时真实检查并修复可修复问题；无工具时回读结构和代码，交付时说明尚未渲染或未操作验证，不能声称交互、视觉或真实实现已经验收。

技能行为发生实质变更时，可选用 [行为回归场景](references/regression-tests.md) 中相关用例评估；场景目录本身不代表测试已运行。
