真实应用或指定操作链路的走查，由 [product-audit](../product-audit/SKILL.md) 按上下文门编排。本 Skill 只解释视觉及交互视觉证据；独立处理设计稿、截图或视频时，按材料和本轮范围选用下列方法。

受编排时复用传入的上下文与证据，返回视觉发现、证据索引和检查范围。需要补采的状态或新背景缺口返回取证入口，不重复启动上游。确认与执行边界见 [团队工作流](../../workflow.md)，产品模型与回写见 [项目记忆规范](../../project-memory-rules.md#轻量产品模型与回写)。

# 高阶交互视觉设计评审

## 触发条件

- 用户上传 UI 设计稿图片（静态图片 → 仅视觉评审，不涉及交互流程评估）
- 用户上传视频/GIF（动态内容 → 视觉评审 + 交互流程问题分析）
- 用户提及"设计评审""交互检查""可用性检查""视觉验收"等关键词
- 用户要求评审真实应用、网页或指定路径中的视觉与交互视觉质量

**文案甄别原则**：区分产品固定文案、用户输入内容和测试数据，不能仅因文案动态出现就认定为用户自定义内容。用户自行填写的内容不按产品措辞验收，但其引发的溢出、层级、可读性问题仍属于视觉评审范围；来源不明时标为待确认。引导提示与占位文案可能是正式产品文案，应核对来源。

## 评审原则体系（四大体系）

### 体系一：尼尔森十大可用性原则

| 序号 | 原则 | 评审要点 |
|------|------|---------|
| 1 | 系统状态可见性 | 当前位置、操作进度和系统状态是否清晰，操作结果与状态变化是否有及时明确的反馈 |
| 2 | 系统与现实世界一致 | 语言、概念和信息顺序是否符合用户熟悉的现实经验 |
| 3 | 用户控制与自由 | 是否有撤销、返回、取消的明确出口和路径 |
| 4 | 一致性与标准 | 产品内的术语、状态与操作是否一致，是否遵循平台约定 |
| 5 | 错误预防 | 是否通过约束、合适默认值或与风险匹配的核对降低出错概率 |
| 6 | 识别而非回忆 | 所需对象、操作和信息是否可见或易于获取，减少用户记忆负担 |
| 7 | 灵活性与使用效率 | 是否支持适合新手的路径，以及适合熟练用户的快捷或定制方式 |
| 8 | 美学与极简设计 | 内容是否聚焦任务，避免无关信息干扰主要内容 |
| 9 | 帮助用户识别、诊断并从错误中恢复 | 是否用用户能理解的语言说明问题，并给出可执行的恢复建议 |
| 10 | 帮助与文档 | 需要时能否找到面向当前任务的帮助，并获得具体操作步骤 |

### 体系二：交互设计八大原则

| 序号 | 原则 | 评审要点 |
|------|------|---------|
| 1 | 安全性 | 操作是否有危险警告，防止误操作 |
| 2 | 一致性 | 交互方式、视觉风格、术语是否统一 |
| 3 | 明确性 | 操作结果是否可预期、无歧义 |
| 4 | 响应性 | 操作反馈是否及时；按任务和已确认性能目标判断，缺少测量时不声称响应耗时达标 |
| 5 | 可控性 | 用户是否掌控操作节奏，可中断/取消 |
| 6 | 高效性 | 常用操作是否快速可达 |
| 7 | 容错性 | 错误是否可恢复，恢复路径是否清晰 |
| 8 | 好学性 | 新用户能否通过探索理解操作 |

### 体系三：格式塔视觉完形原则

| 序号 | 原则 | 评审要点 |
|------|------|---------|
| 1 | 接近性 | 相关元素是否靠近，间距是否体现关系亲疏 |
| 2 | 相似性 | 同类元素是否具有一致的视觉特征（颜色、形状、大小） |
| 3 | 连续性 | 视觉路径是否引导自然阅读顺序 |
| 4 | 闭合性 | 信息是否通过暗示形成完整图形，减少认知负担 |
| 5 | 图形-背景 | 主体与背景是否分离清晰，对比度是否足够 |
| 6 | 简单性 | 信息是否按简洁原则组织，减少视觉噪音 |
| 7 | 局部优先 | 细节是否在整体中清晰可辨，层级关系是否明确 |
| 8 | 稳定性 | 视觉重心是否稳定，不漂浮，信息分布均衡 |

### 体系四：WCAG 无障碍四大原则

| 原则 | 评审要点 |
|------|---------|
| 可感知性 | 文字与背景对比度、图像替代文本、音频/视频字幕 |
| 可操作性 | 键盘可访问性、焦点可见、足够操作时间、无眩晕触发 |
| 可理解性 | 语言清晰、错误可识别、操作逻辑一致 |
| 健壮性 | 跨浏览器/设备兼容性、语义化结构 |

## 视觉评审维度清单

按本轮目标选择适用维度，检查状态采用 [统一判定规则](../product-audit/SKILL.md#主结论与证据阈值)。截图不能证明键盘可访问性、完整状态转换、实际响应耗时或跨设备兼容性；需要相应操作记录、代码或测量才能支持此类判断。

| 维度 | 检查内容 |
|------|---------|
| 页面布局 | 留白是否合理，视觉重心是否均衡，内容密度是否适当 |
| 内容层级 | 信息优先级是否清晰，主要/次要/辅助层级是否可辨 |
| 组内一致性 | 同分组同类型元素样式是否统一 |
| 配色 | 色彩体系是否和谐，对比度是否达标，情感调性是否匹配 |
| 字体 | 字体层级是否清晰，衬线/无衬线是否恰当使用 |
| 间距 | 元素间距是否体现语义关系，呼吸感是否适当 |
| 圆角 | 圆角数值是否统一，风格是否一致 |
| 图标 | 图标风格是否统一，尺寸是否协调，语义是否准确；没有合适 emoji 时是否避免强行使用，并改用 CSS/HTML、SVG 或统一图标库 |
| 阴影统一度 | 阴影层级是否一致，投射角度/模糊度是否协调 |

## 专业判定规则

### 元素分组识别

依据可见结构识别页面元素分组类型：

| 分组类型 | 定义 | 示例 |
|----------|------|------|
| 模块分组 | 功能/区域层面的自然分割 | 顶部导航、内容区、底部Tab |
| 语义分组 | 信息内容层面的关联性 | 标题+正文、标签+输入框 |
| 类型分组 | 同类元素的使用场景一致 | 所有主按钮、所有次要操作 |

### 元素层级拆解

```
模块级 → 组件级 → 元素级 → 细节级
```

### 样式一致性要求

仅要求：同分组 + 同类型 + 同场景的元素保持样式统一，不做过度约束。

### 模糊问题处理

遇以下情况统一标注「💡 建议验证」，不直接判定为设计问题：

- 疑似对比度不达标（需工具实测）
- 可疑的间距/尺寸不一致（需精确数据）
- 疑似层级问题（需上下文确认）

## 报告组织

正式主结论、严重度和验证层级统一引用 [主结论与证据阈值](../product-audit/SKILL.md#主结论与证据阈值)，不另设视觉评级。受 product-audit 编排时返回专业发现，由上游给出合并主结论；独立评审时先读取该规则，并将结论限定为当前视觉或交互视觉范围。

报告按需包含：

1. **范围与判断**：评审材料、页面/状态、证据边界及结论依据。
2. **视觉动线**：当动线有助于解释问题时，说明实际观察到的阅读顺序与信息层级，不套用固定 Z/F 路径。
3. **问题与建议**：按影响排序，记录位置和证据、适用原则、用户影响及可执行改法。“流程”“一致性”“文案”只是类别，不直接决定严重度。
4. **覆盖与缺口**：说明已检查的适用维度、缺失的状态或测量及后续验证责任。无法确认的疑似问题放在缺口中。

可使用以下单项格式，不要求填满全部分类或附完整原则打分表：

```text
[问题名称]
位置与证据：[页面/步骤，以及截图、操作记录或测量结果]
专业依据：[适用原则，不适用的原则省略]
用户影响：[影响及严重度依据]
建议：[可执行改法]
```

## 素材类型差异化处理

| 素材类型 | 视觉评审 | 交互流程评审 |
|----------|---------|------------|
| 静态图片 | 检查可见视觉，不可测项标待验证 | 不推断未展示的流程、动效或响应时序 |
| 视频/GIF | 检查可见视觉 | 只评估素材实际展示的路径、状态与时序 |
| 本轮真实操作及截图 | 检查已采集状态 | 检查实际执行并留有证据的路径；未执行分支标待验证 |

## 评审原则优先级

评审时优先检查高优先级原则，高优先级发现问题时继续检查但重点标注：

1. 尼尔森十大可用性原则与交互设计八大原则：检查任务可完成、反馈和恢复。
2. WCAG 无障碍四大原则：检查本轮有证据支持的可访问性问题。
3. 格式塔视觉完形原则：检查感知分组、层级和视觉动线。

这是检查顺序，不是问题严重度。无障碍缺陷造成核心阻断时同样优先处理；静态截图不能证明 WCAG 合规。
